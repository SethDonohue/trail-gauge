# Rebuilding 0.3.0 (November 2026)

TrailGauge 0.3.0 was built in a separate conversation, and its source never reached this
repository. The GitHub builds 2 to 8 came from older code, and because they had higher version
numbers they replaced 0.3.0 when installed. The 0.3.0 APK was restored as the
[v0.3.0 release](https://github.com/SethDonohue/trail-gauge/releases/tag/v0.3.0) (it lives on the
`release-assets` branch), and its features were rebuilt here as **0.4.0**.

The 0.3.0 APK's compiled JavaScript (Hermes bytecode) was decoded for its user-facing text,
constant names and module names. That text, which states most rules and numbers outright, is the
reference for 0.4.0. Logic was rewritten, not copied.

## What 0.4.0 restores

| 0.3.0 feature | In 0.4.0 |
| --- | --- |
| Setup guide (first run, reopenable) | Location, nearby devices, battery settings, mounting, first-page gauges, zero |
| Guides & tips | 10 topics, 0.3.0 wording: outside and cabin sensor placement, traffic heat, window fog, mounting, compass, altitude, no OBD-II/CAN, alerts, orientation |
| Gauges three at a time, swipe sideways | First page is your three; the rest follow, three per page |
| Hold ZERO (top right) | Hold 0.8 s; a tap does nothing |
| MUTE on the dashboard, speaker button on each gauge | Same; muted gauges show a crossed speaker |
| Alert beeps and vibration | First entry to amber or red; red repeats every 30 s; demo data never beeps; media volume |
| Quick settings | Mute, lock view, night mode and dimming, units, orientation, keep screen on |
| Lock view while moving (settings never locked) | Above 8 km/h (5 mph) double-tap and swipes do nothing; manual lock in quick settings |
| Night mode and dimming | Light sensor, else sun elevation at your GPS position, else the clock |
| Gauge colour (presets and custom) | Presets including "90s green"; custom hues that stay readable and never look like amber/red |
| Cabin temperature and humidity gauges | Frame V3 from the hub; dew point; window fog risk (3 °C margin) |
| Outside temperature correction | Rises at most 0.5 °C/min below 30 km/h; keeps the last good reading after start-up |
| Second outside sensor | Lower reading wins; warns if they differ by more than 5 °C |
| Compass calibration, north reference, manual declination, heading offset | Advanced settings |
| QNH entry (hPa or inHg), altitude offset | Advanced settings |
| Tilt smoothing, tilt number update rate, phone sensor rate | Advanced settings |
| Vehicle data bus: CAN/OBD-II or None | A CAN error is not a fault on vehicles without a bus |
| Hub status and faults | Settings > Hub |
| Upright N/E/S/W on the compass | Letters move round the card but stay upright |

0.4.0 also keeps everything built here since: tablet and split-screen layouts, the altitude
source setting (barometer or GPS), the tilt/compass sign fix, the app icon, iOS support, contrast
fixes and CI.

## Where 0.4.0 may differ from 0.3.0

These values were not visible in 0.3.0's text, so they are reasoned choices. Tell me if 0.3.0
behaved differently and I'll match it.

- Ice-risk default 3 °C (37 °F); cabin warning default 35 °C (95 °F), red 5 °C above.
- Night: light below 10 lux for 8 s turns night on, above 40 lux turns it off; sun below −4°;
  clock 20:00 to 06:00.
- Compass calibration needs 150 samples and 40 µT of sweep on two axes.
- Gauge colour presets other than mint and "90s green".
- The exact steps and order of the setup guide.
- Telemetry frame V3 layout (defined in `app/src/core/frame.ts`): 0.3.0's exact byte layout was
  not recoverable, so hub firmware must follow this definition.
- Settings saved by 0.3.0 are kept where the names match (both used `trailgauge.settings.v1`);
  anything unrecognised falls back to defaults.
