# TrailGauge: instructions for Claude

Off-road telemetry for a 12 V vehicle: a dash-mounted hub with remote sensor nodes (not built yet), and a dashboard app on the owner's phone (Galaxy S24). The owner has no computer: everything is built in the cloud and installed on the phone from a GitHub Release. They read on a phone screen, so explain things simply and briefly.

The spec is `docs/spec/trailgauge-spec-rev-b.md`; open work is in `TODO.md`.

## Stack
- App in `app/`: Expo SDK 58 + React Native 0.88, TypeScript, Skia, Reanimated, react-native-ble-plx. Not Capacitor.
- Android first (package `com.trailgauge.app`). iOS builds in CI only (`ios-simulator.yml`); no TestFlight.
- Logic and math in `src/core`, data sources and services in `src/engine`, gauges in `src/gauges`, screens in `src/ui`. Unit tests in `test/`.
- Settings and calibration are stored with AsyncStorage (`src/engine/settings.ts`).

## How we work
- One feature at a time. After each one, publish a build so it can be tested on the phone before moving on.
- Before multi-file changes, give a short plain-language plan and wait for an OK.
- Make minimal, focused changes. Follow existing patterns and naming. Ask before adding any new dependency.
- Keep pure logic in `src/core` with a unit test, so it can be checked without a device.
- Never claim something works until it type-checks, tests pass and CI builds it. Emulators can't prove sensor direction, compass or altitude: tell the owner exactly what to check on the phone.

## Design decisions (keep these)
- **Settings are never locked by speed.** Keep the speed-lockout logic (`src/core/moveLock.ts`) for future use, e.g. locking the double-tap exit from gauge views.
- Compass N/E/S/W letters stay upright as the dial turns.
- **ZERO** (calibration) stays at the dashboard's top right; it's used often.
- Single taps on gauges do nothing, so trail bumps can't switch views. Double-tap and swipes are the gestures.
- Heavy display smoothing must never delay a warning: CAUTION/DANGER colours and alerts use a fast reading.
- Demo data never beeps.
- Guides & tips are always reachable, including sensor placement tips.
- **Must work without CAN bus or OBD-II.** It's also for older vehicles, so never make a feature depend on them.

## Hub and protocol
- The app speaks the Rev B BLE protocol (telemetry frames V2/V3, parsed in `src/core/frame.ts`). A new field means a new frame version; keep older versions parsing.
- Cabin temperature, humidity and a second outside sensor need frame V3.
- Sensor power: each sensor board takes power from a nearby 12 V circuit (not lighting circuits), with an optional rechargeable/swappable NiMH or LiPo backup. No cable runs from a central point or the battery.
- Hub hardware and firmware aren't started. Parts list: `docs/hardware/hub-bom.md`.

## Build and release
- Every push to `main` that touches `app/**` runs `.github/workflows/android-apk.yml`, which type-checks, runs tests, builds the APK and publishes a release named `build-<run number>` with `trailgauge.apk`. To rebuild without a code change, run that workflow by hand (Actions > Android APK > Run workflow).
- Before pushing, in `app/`: `npx tsc --noEmit` and `npm test` pass.
- Version: bump `version` in both `app/package.json` and `app/app.json` (they must match). Don't hand-edit `versionCode`; CI sets it from the run number so each APK installs over the last.
- After pushing, watch the run and confirm the release and APK exist.
- **Always send the owner the install link**: https://github.com/SethDonohue/trail-gauge/releases/latest/download/trailgauge.apk (or the release page), and list what to test on the phone.
- `app/android` is generated by `expo prebuild --clean` in CI and isn't committed. Make native changes through `app.json` or config plugins, never by editing generated files.
- Building inside a Claude workspace is a fallback only: `bash scripts/build-apk.sh` from `app/` (slow; see `app/HANDOFF.md` for its workarounds).
- Don't change the package name or signing (the standard debug key from prebuild). With a different key the APK won't install over the current app, and uninstalling wipes settings and calibration.
- If the layout changes, check the tablet screenshots from `tablet-screens.yml` on the `ci-screenshots` branch.

## Data
- Updates must keep settings and calibration. A new setting gets a default; never reset or rename stored keys without a migration.

## Mobile UI
- Built for a mounted phone in a moving vehicle: dark theme, large readable numbers, big touch targets, nothing that a bump can trigger.
- Phones default to landscape lock; tablets and split screen (beside Gaia GPS / onX) must keep working.
- Handle the Android back button on every screen.
